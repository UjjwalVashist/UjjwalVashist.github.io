LLM Risk Radar

Companies are rolling out AI assistants faster than staff learn the risks. This is a weekly digest of AI-security news, sorted by the OWASP Top 10 for LLM Applications, that builds and publishes itself every Monday.

How it works

  1. Read: fetches 13 RSS and Atom feeds, including heise Security, the BSI, NCSC UK, Google and Microsoft security blogs.
  2. Filter: general security news is kept only when it mentions an AI term such as AI, LLM, KI or ChatGPT, matched as whole words.
  3. Sort: each OWASP risk has keyword lists in English and German. The risk with the most hits wins; a hit in the title counts double. No hit means "Other AI security news".
  4. Publish: writes a static site with the current week, an archive, a trend table and the ten risks in plain words.
  5. Schedule: GitHub Actions runs the tests and the update every Monday and commits the new pages to GitHub Pages.

Why keyword rules and not an AI model

Every decision can be explained ("this headline matched prompt injection"), tested and reproduced, and it costs nothing to run. The price is accuracy: rules miss items that describe a risk in other words. The share of "Other" shows how much the rules don't cover, and improving a rule means editing one line of config.

"Using AI safely" sheet

The site also has a printable one-page sheet in English and German ("KI sicher nutzen"): eight everyday rules for people who use AI assistants at work, such as keeping confidential data out of public tools and reviewing AI-written code before running it. Each rule names the OWASP risk it protects against.

Security of the tool itself

Feed content is untrusted input. Everything is HTML-escaped before it reaches the page, and a test checks that a headline containing a script tag can't inject code into the site.
